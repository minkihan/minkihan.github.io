book CLI에서 출발한 LLM 작업 도구를 재설계. 앞선 도구는 과거 작업을 색인해 주입하는 데 머물렀고, 정작 어떤 절차로 일할지는 매 세션 LLM이 문서를 새로 해석해 판단했다. 해석은 매번 달라지고 틀려도 조용히 통과하기 때문에, 절차 자체를 코드로 고정한 자체 파이프라인.

// 단계마다 게이트가 실제 명령을 돌려 판정하고, 통과하지 못하면 다음 단계로 가지 못한다
  • 플랜 수립, 승인, 설계, 구현, 시험, 배포, 문서화, 리포트까지 단계별 파이프라인을 Go로 자체 설계
  • 단계마다 통과 조건을 코드로 고정, 게이트가 실제 명령을 실행해 판정하고 조건을 채우지 못하면 다음 단계 진입을 차단
  • 모든 명령이 JSON 봉투 한 줄과 다음에 실행할 명령 목록을 반환하는 계약으로 통일해, LLM이 절차를 추측하지 않고 지시받은 명령만 실행
  • 지식 저장소 자체 구현: 추가 전용 개정 이력, 별칭 기반 경로 이동, 갈래별 본문 계약 검증, 저장 경계에서 품질 하락만 선별 차단
  • 런마다 git 워크트리를 분리해 동시 작업 간 간섭을 막고, 서브에이전트를 병렬로 실행
  • 외부 LLM 교차 검토를 파이프라인 단계로 내재화, 게이트가 실제로 검사하는지 역으로 확인하는 변조 테스트를 도입해 재는 것 없이 통과하던 게이트를 적발
